## 1. Zero-Trust Architecture & IAM Identity

Vidoxis operates under strict zero-trust principles across all production components:

### 1.1 Absolute Ban on Service Account Keys
* **Rule:** No service account JSON key files (`*.json`) may ever be generated, stored on disk, or committed to source control.
* **Enforcement:** Cloud Run microservices authenticate using **Workload Identity Federation (WIF)**. When interacting with target GCP demo projects, workers use `roles/iam.serviceAccountTokenCreator` to mint short-lived (15-minute) OAuth access tokens held exclusively in volatile RAM.

### 1.2 Session Vault Security (KMS Envelope Encryption)
* Chrome user profiles (`user-data-dir`) stored in Google Cloud Storage are encrypted using Google Cloud Key Management Service (Cloud KMS) with 256-bit AES-GCM Customer-Managed Encryption Keys (CMEK).
* Profiles are decrypted on container boot directly into an in-memory `tmpfs` RAM disk at `/dev/shm/chrome-profile`. The session never writes to persistent disk and vaporizes when the Cloud Run container terminates.

## 2. Blast-Radius Protection: Immutable Project Regex Guardrail

To prevent automated teardown scripts from targeting real corporate environments, all destructive commands (`terraform destroy`, `gcloud projects delete`) are gated by a compiled binary assertion:

```typescript
export function assertSafeSandboxProject(projectId: string): void {
  const SAFE_SANDBOX_REGEX = /^(?:vidoxis|trainex)-(sandbox|ephem)-[a-z0-9]{4,8}$/;
  if (!SAFE_SANDBOX_REGEX.test(projectId)) {
    throw new Error(
      `FATAL SECURITY VIOLATION: Operation refused on project '${projectId}'. ` +
      `Target project ID does not match ephemeral sandbox naming convention: ${SAFE_SANDBOX_REGEX}`
    );
  }
}
```

## 3. PII, NDA & Enterprise Confidentiality Protections

Every video generated by Vidoxis undergoes a mandatory, automated three-tier redaction pipeline before rendering:

1. **Bounding Box Blurring:** Telemetry logs from the CDP runner identify sensitive element coordinates (billing accounts, user avatars) and apply a 24px Gaussian blur shader.
2. **OCR Anomaly Scrubber:** OpenCV and Tesseract inspect every 15th frame for text matching:
   - Billing Accounts: `\b01[0-9A-Z]{4}-[0-9A-Z]{6}-[0-9A-Z]{6}\b`
   - Corporate Emails: `[a-zA-Z0-9._%+-]+@google\.com`
   - Internal Project Prefixes: `\bcorp-[a-z0-9-]+\b`
3. **Fail-Closed Audit:** If any unmasked match is detected with confidence $>0.85$, the build is aborted immediately.

## 4. Static Application Security Testing (SAST)

All pull requests and code modifications must pass automated security scanning:
* **Dependency Vulnerabilities:** `npm audit --audit-level=high`
* **Secret Leak Detection:** Scans for GCP API keys (`AIzaSy...`), private keys, and authorization headers.
* **SVG XSS Sanitization:** All SVG architecture diagrams generated via PromptCanvas are sanitized with DOMPurify to prevent malicious script injection.

## 5. Vulnerability Disclosure

If you discover a security vulnerability in Vidoxis, please report it immediately to the security team at `security@vidoxis.google.internal`. Do not open public GitHub issues for security vulnerabilities.
